# השלמת השחרור לחנות

הקבצים בתיקייה זו מתעדים פערים ואישורים אמיתיים. אין להחליף שדה חסר בערך לדוגמה או לסמן בדיקה שעוד לא בוצעה כאילו עברה.

## פרטים וראיות

1. להשלים ב־store-readiness.json את שם המפעיל, שם המפתח, כתובת ופרטי קשר אמיתיים. לעדכן בהתאם את privacy.html, support.html ו־terms.html ולפרסם דפי HTTPS ציבוריים. אין לפרסם את אפליקציית Web המלאה בלי השלמת גילוי ספק האחסון והשמירה בלוגים.
2. להריץ `npm run store:inventory`. הדוח המלא ב־reports/store-readiness.json מכיל SHA-256 ונתיב של כל מדיה נארזת. זהו מלאי נוכחי, בנפרד ממרשם הזכויות ההיסטורי. כל קובץ שנמצא ב־public נארז, גם אם הוא אינו בשימוש במסך הפעיל.
3. להוסיף ל־media-approvals.json רשומות עם `assetHashes`, `evidencePath`, `evidenceSha256` ו־`commercialDistribution: true` רק לאחר בדיקת ראיות מתאימות. רשומה אחת יכולה לקשר קבוצת קבצים לאותו מסמך מאומת. לשמור ראיות בתוך הריפו רק אם הן מתאימות לאחסון בו ואינן כוללות סודות או מידע אישי שלא נועד להיחשף.
4. להשלים את בדיקות המכשירים, הביקורת החינוכית, שימוש הילדים, המותג והצהרות Play. לכל אישור בשדה approvals נדרשים `evidencePath` ו־`evidenceSha256`; הראיה צריכה לתאר את הבדיקה, תאריך, גרסה ותוצאה. בדיקת החינוך מאמתת הבנת הוראות והתאמה לגיל, ואינה היתר לטעון ליעילות מוכחת.
5. בסיום השינויים והבדיקות להעתיק את `inputFingerprint` מהדוח לשדה המקביל ב־store-readiness.json. שינוי בקוד, בתוכן, במדיה או בתלויות ידרוש אישור מחדש. חתימת QA אינה נוצרת אוטומטית.
6. להריץ `npm run store:check`. ההרצה בודקת גם אבטחה ותקינות דפי הפרטיות והתמיכה הציבוריים. ה־workflow החתום משתמש באותו שער לפני העלאה.

בדיקה אוטומטית יכולה לוודא שקיימת ראיה ושהיא לא השתנתה. היא אינה יכולה לקבוע בעצמה שמסמך מעניק זכויות מסחריות או להחליף שיקול דעת מקצועי.

## Android — בדיקות על הגרסה המותקנת

לבנות ולהתקין בטלפון חלש/ישן, בטלפון עדכני ובטאבלט. לרשום דגם, גרסת Android, גרסת WebView, מקור ההתקנה, versionCode ו־SHA-256 של ה־APK/AAB. בדיקות דפדפן אינן תחליף לכך.

| תרחיש | תנאי קבלה | תוצאה/ראיה |
|---|---|---|
| פתיחה ראשונה במצב טיסה | תפריט, פרופיל, תמונות, משחק וקריינות ארוזה פועלים | טרם נבדק |
| כל שמונת המשחקים וארבעת העולמות | כניסה, טעות, רמז, הצלחה וסיכום בלי תקיעה | טרם נבדק |
| מסך קטן וסיבוב | כפתור הפעולה נגיש, אין חיתוך של הוראות או safe areas | טרם נבדק |
| Back, רקע וחזרה | ניווט צפוי, קול נעצר וחוזר לפי ההגדרות | טרם נבדק |
| הריגת תהליך לאחר שלב | השלב שנשמר חוזר ללא תגמול/ראיה כפולים | טרם נבדק |
| שדרוג על התקנה עם התקדמות | פרופילים, אוספים והעדפות נשמרים | טרם נבדק |
| כשל כתיבה ואז ניסיון חוזר | אין הצלחה מדומה; הנתונים שלא נכתבו נשמרים לאחר Retry | טרם נבדק |
| פרופילים ומחיקה | בידוד בין ילדים ומחיקה רק לאחר אישור מבוגר | טרם נבדק |
| שימוש ממושך | זמן פתיחה, זיכרון, תגובת מגע, חום ויציבות מתועדים במכשיר חלש | טרם נבדק |
| Play pre-launch | אין crash/ANR/כשל קריטי בלתי פתור; הרשאות והצהרות תואמות | טרם נבדק |

הסביבה הנוכחית אינה כוללת מכשיר מחובר או אמולטור מותקן. בדיקות ה־instrumentation החדשות ל־AtomicLearningStore ניתנות להרצה עם `node scripts/run-gradle.mjs :app:connectedDebugAndroidTest` לאחר חיבור מכשיר/אמולטור מתאים; הפקודה מריצה בדיקות מקומיות ואינה מפרסמת בחנות.

לאחר `npm run build:native:release` ובניית APK, להריץ `npm run android:verify:apk` עם ANDROID_SDK_ROOT מוגדר. הסקריפט משווה את כל נכסי Production לבינארי, בודק זהות ו־SDK, חתימה, יישור ZIP והיעדר הרשאות מערכת או ספריות ELF. הרשאת AndroidX הפנימית ל־receiver מותרת רק עם הגנת signature. בדיקה זו אינה בדיקת התקנה או אישור של AAB חתום להפצה; דוח הבדיקה מציין אם הבינארי debuggable.

## מפגשי שימוש וביקורת תוכן

לבצע מפגש בהסכמת ובהשגחת הורה, ללא העלאת שמות/תמונות/הקלטות ילדים לריפו. להשתמש במזהה אנונימי, קבוצת גיל ודגם מכשיר. לכסות גילאי 3–6, במיוחד גיל 3 וגיל 6, ומטלות עם בחירה, גרירה, ספירה, אותיות ורמזים.

לרשום: האם ההוראה הובנה ללא הסבר נוסף; האם היעד החזותי ברור; האם הטעות והרמז עוזרים; האם הילד מצליח לגעת/לגרור; משך הסבב; סימני תסכול; תיקונים נדרשים. איש/אשת החינוך יבדקו גם הגייה, התאמת רמה והמשמעות של ״שליטה״ בדוח להורה. להפריד תצפית משתמשים מטענה לשיפור למידה.

קבוצות גיל בחנות: המוצר מכסה 3–6. הבחירה המוצעת ב־5 ומטה וב־6–8 חייבת לעבור אישור מקצועי והחלטת מיצוב; אין כאן ראיה אוטומטית להתאמה לגיל 7–8. אין לשנות את טווח הגילים במוצר כדי לעקוף את הבדיקה.

## חתימה ומספרי גרסה

בנייה לחנות דורשת את כל משתני ANDROID_KEYSTORE_* / ANDROID_STORE_PASSWORD / ANDROID_KEY_ALIAS / ANDROID_KEY_PASSWORD ואת ANDROID_VERSION_CODE. Gradle חוסם Release לא חתום. Fastlane מקצה מספר גבוה ממספרי הגרסה הקיימים בארבעת מסלולי Play הרגילים; אם הוספתם מסלולים מותאמים אישית, יש להוסיף אותם לרשימת המסלולים. העלאות מקבילות מחוץ ל־workflow צריכות להשתמש באותו מנגנון תיאום.

יש לשמור את מפתח ההעלאה וגיבויו במקום מוגן. אין להעתיק סודות לתיעוד. Internal Testing אינו מחליף Closed Testing כשהחשבון מחויב בו. לא תבוצע הפצה עד להשלמת החסמים והבדיקות.
